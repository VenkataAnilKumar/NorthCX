# Feature research: agent platform, user platform and admin platform (November 2026)

Status: **Reference**. Updated: 2026-11-09. Master for: research notes on other products (the only folder where they are named). Research notes, not a commitment. This is the one place in the repository where other companies' products are named; the product itself depends on none of them. **Evidence quality is low to medium:** nearly every source below is a vendor blog, buyer guide or comparison page written to sell something. Treat each claim as "what the market is saying", not as measured fact. The two firmer sources are the OpenTelemetry specification pages and an academic survey of agents in production. Searches were run on 2026-11-09; each ran once, so coverage is partial.

## What the sources agree on

**1. Governance is a buying criterion on par with capability.** Customer-service buyer guides now weigh admin controls, guardrails, audit trails and analytics equally with automation features ([Lorikeet comparison](https://www.lorikeetcx.ai/articles/best-ai-support-automation-platforms-compared-2026), [Decagon enterprise features](https://decagon.ai/resources/enterprise-conversational-ai-features), [Fini governance guide](https://www.usefini.com/guides/ai-support-platforms-governance-approval-controls-audit-logs)). Described features: an admin console showing who uses the AI and for what; role-based limits on which models or features a team may use; conversation-level audit logs; separate models that check the main agent's output against policy before it reaches the customer ([Konverso roundup](https://www.konverso.ai/en/blog/6-best-customer-service-ai-agent-platforms-in-2026)).

**2. The enterprise admin checklist is stable.** SSO plus SCIM (deprovision in minutes, enforce MFA and session rules), a small set of roles (admin, builder, operator, viewer) plus custom roles, an agent registry or catalog (owner, business purpose, environment, model), per-agent budgets and rate limits tied to the agent's identity, and audit events that record user, agent, tool, redacted parameter class, outcome and the approval reference ([Pokee buyer's guide](https://pokee.ai/blog/enterprise-ai-agent-platform-guide), [MintMCP comparison](https://www.mintmcp.com/blog/agent-management-platforms-compared), [Gravitee catalog notes](https://gravitee.io/corpus/gen-948/web-business-management-system/ai-agent-service-catalog-and-lifecycle-management-for-enterprise-web-business-platforms.html), [Jannik Reinhard on a control plane](https://jannikreinhard.com/enterprise-agent-control-plane/)).

**3. MCP is becoming an enterprise requirement, with governance gaps.** The 2026 roadmap lists enterprise readiness and audit trails as a priority; enterprise-managed authorization (access routed through the company's identity provider) was reported as stabilized in June 2026; a July 2026 revision added a stateless Streamable HTTP transport; explicit MCP support is showing up in procurement requirements ([WorkOS on the roadmap](https://workos.com/blog/2026-mcp-roadmap-enterprise-readiness), [CData](https://www.cdata.com/blog/2026-enterprise-mcp-adoption-roadmap), [Snowflake on MCP gateways](https://www.snowflake.com/en/blog/engineering/enterprise-mcp-gateway-ai-agent-governance/)). Several sources warn that MCP is an access layer with weak default governance. These are secondary reports; the MCP specification itself should be read before building.

**4. Telemetry is converging on OpenTelemetry's GenAI conventions, which are not stable.** The agent conventions define `create_agent`, `invoke_agent` and `execute_tool` operations (tool spans named `execute_tool {tool_name}`), and tool failures propagate error status to the parent span. The official pages still mark them as in development, and a June 2026 claim that they were stabilised conflicts with that ([OpenTelemetry agent spans](https://opentelemetry.io/docs/specs/semconv/gen-ai/gen-ai-agent-spans), [GenAI spans](https://opentelemetry.io/docs/specs/semconv/gen-ai/gen-ai-spans), [Honeycomb on agent timelines](https://www.honeycomb.io/blog/instrumenting-ai-agents-agent-timeline-opentelemetry-guide)).

**5. Evaluation practice in customer support: people first, judges calibrated.** A production study of deployed agents reports human review (74 percent) and LLM judges (52 percent) far ahead of rule-based checks (42 percent) ([Measuring Agents in Production](https://arxiv.org/pdf/2512.04123)). Practitioner guidance: calibrate a judge against a few hundred human labels before trusting it; use binary pass/fail for regression gates; put approval gates only on risky, irreversible or customer-facing actions, because a synchronous gate on a 30-second support reply is too slow, so sample and batch-review instead; feed reviewer rejections back into the regression set ([Statsig](https://statsig.com/perspectives/humanloopevals-automationlimits), [n8n playbook](https://blog.n8n.io/production-ai-playbook-human-oversight), [Microsoft Learn module](https://learn.microsoft.com/en-us/training/modules/aaai-design-human-in-loop-approval-workflows/7-summary)).

**6. QA and agent-assist tools score every conversation.** Scorecards, 100 percent coverage instead of a small sample, real-time suggested articles for staff, and QA for AI agents as well as people ([Level AI guide](https://thelevel.ai/blog/customer-support-quality-assurance-tools), [Kaizo](https://kaizo.com/blog/customer-service-quality-assurance-software/), [Typewise](https://www.typewise.app/blog/qa-scoring-platforms-ai-support)). One reviewer notes a leading tool lacks calibration sessions and reviewer assignment, and users report scoring errors needing manual correction (a vendor-written comparison; weak evidence).

## Candidate additions, in the order I would take them
1. **Admin visibility view** from audit and traces (no new storage). Small, directly answers the first buying criterion.
2. **Agent catalog fields** (owner, purpose, environment, model) on agent specs and the agent list. Small; needed before the catalog in WP3.6.
3. **Agent-action audit records** with the approval reference. Medium; strengthens the audit story and feeds the MCP work.
4. **OpenTelemetry GenAI mapping** for the existing OTLP export. Small; low risk if labelled experimental.
5. **Scheduled review sampling, outlier sweeps and reviewer calibration** on top of the review queue. Medium; supports E7 and the judge calibration needed for release.
6. **Analytics-only role.** Small; touches the permission tables and every sweep test.

## 8. Coding and general agent platforms (searched 2026-11-09)
These are not customer-service products, but they set what people now expect from an agent workbench. Same caveat: product pages and third-party write-ups, no interface captures.
- **OpenAI Codex app:** a project sidebar, a list of concurrent agent threads with status, and a review pane where changes are inspected and commented on before they are applied; each task gets an isolated work copy so parallel agents do not collide. Sources disagree on whether agents run locally or in the cloud (both are reported), and one July 2026 guide says the app was merged into the ChatGPT desktop app as one of three modes, which I could not confirm ([Codex app docs](https://developers.openai.com/codex/app), [TechInformed](https://techinformed.com/openai-ships-codex-macos-app-as-ai-coding-shifts-toward-parallel-agents/), [Verdent](https://www.verdent.ai/guides/what-is-codex-app)).
- **Claude Code desktop app:** rebuilt in April 2026 around parallel sessions: a sidebar lists sessions, each with its own chat history, project folder and changes, and several run at once; users report sessions missing from the sidebar after restarts and sessions started in the terminal not appearing (user-filed issues) ([Anthropic's redesign post](https://claude.com/blog/claude-code-desktop-redesign), [desktop docs](https://code.claude.com/docs/en/desktop), [MacRumors](https://macrumors.com/2026/04/15/anthropic-rebuilds-claude-code-desktop-app)). I found nothing on the Claude Console's admin screens.
- **GitHub Copilot:** the coding agent and third-party MCP servers are off by default and an organisation admin switches them on under Settings, Copilot, Policies; admins choose which repositories the agent may use and whether partner agents are allowed; an enterprise level sits above organisations and its settings cannot be overridden below ([manage policies](https://docs.github.com/en/enterprise-cloud@latest/copilot/how-tos/administer-copilot/manage-for-organization/manage-policies), [agent control plane](https://github.blog/changelog/2025-10-28-enterprise-ai-controls-the-agent-control-plane-are-in-public-preview/)). I did not find the agents panel the question mentioned.
- **MiniMax:** two products: a browser agent (experts, custom and fast modes, branching a session, slides, an MCP builder; closed-source platform) and a separate desktop app that combines chat, a project workspace, files, terminal, browser preview, skills, memory and automation in one local workspace ([MiniMax Agent docs](https://agent.minimax.io/docs), [changelog](https://agent.minimax.io/docs/changelog.md), [MIT AI Agent Index](https://aiagentindex.mit.edu/2025/minimax-agent)).

**What carries over to NorthCX:** the working surface is a list of parallel threads on the left, the conversation in the middle and the work product (changes, drafts, sources) on the right, which is the staff workspace layout already drawn; people expect several threads open at once with visible status; administration lives in separate policy pages with default-off for risky capabilities, per-scope switches (which repositories, which partner agents) and inheritance from a higher level that lower levels cannot override. That last point suggests the admin design should show where a setting comes from (platform, tenant, team, agent) and whether it is locked.

## 9. What the Claude Code desktop app's layout looks like (from Anthropic's pages, 2026-11-09)
I cannot capture screenshots of the app, so this is text from the [redesign post](https://claude.com/blog/claude-code-desktop-redesign) and the [desktop documentation](https://code.claude.com/docs/en/desktop) (the second was read only in part). Two comparable summaries of other products follow the same split of work surface and administration (sections 7 and 8).
- **Sidebar:** all active and recent sessions in one list, filterable by status, project or environment and groupable by project; a New button; View all opens an Archived tab; Customize manages connectors, skills and plugins; Option-click a session to open it beside the current one.
- **Session title bar:** buttons that open panes (Terminal, Changes, Browser, Files), a menu for the rest (background tasks, plan, show or hide the session rail), and a session menu with transcript views (Verbose, Normal, Summary).
- **Panes:** chat, diff, browser, terminal, file, plan, tasks and subagent panes that can be dragged into a grid, resized, popped out into their own window and docked back; a side chat that branches from the main thread without adding to it.
- **Session details column:** cards showing where the session runs, what changed, what is running, and context-window use.
- **Prompt area:** the box, a plus button for files, skills, connectors and plugins, and a row with the environment, project folder, permission mode, model and a usage ring. Permission modes: Manual (asks before edits and commands), Accept edits, Plan (propose without editing), Auto (a background classifier checks actions) and Bypass.
- **Administration:** preferences under Settings; organization admins can enforce some settings through managed settings, and centrally managed plugins apply in the app.
What this suggests for the staff workspace (design doc, session-style variant): a grouped thread list, a title bar that opens panels, a details column, and a row under the reply box with the mode and budget; the permission-mode idea maps to a reply mode (draft only, review before send, send).

## 11. Hybrid local and cloud model selection (searched 2026-11-09)
Most sources are practitioner blogs; the numbers they quote are unverified.
- **Common pattern:** three tiers (on-device or local, private cloud, public cloud); the router first asks whether the cheaper or local model can handle the request at all, then weighs quality difference, latency and cost; privacy rules can override cost, for example when personal data may not leave the premises ([Hybrid cloud-edge routing](https://tianpan.co/blog/2026-04-10-hybrid-cloud-edge-llm-inference-routing), [Eden AI](https://www.edenai.co/post/hybrid-ai-provider-strategy), [elinkdesign](https://www.elinkdesign.com/hybrid-ai-architecture-cloud-routing-local-models-for-privacy-and-savings)). Claimed savings of 60 to 90 percent by sending most work local are vendor-leaning and not independently validated.
- **Routers and cascades:** RouteLLM is an up-front router between a strong and a weak model, trained on human preference data, evaluated on general chat and knowledge benchmarks (not customer support); the often-quoted figure of about 85 percent cost reduction at 95 percent of the strong model's quality is secondhand. A cascade tries the cheap model and escalates when a check fails; sources stress the quality check is the hard part ([RouteLLM paper](https://arxiv.org/abs/2406.18665), [LMSYS post](https://lmsys.org/blog/2024-07-01-routellm/), [NeuralTrust overview](https://neuraltrust.ai/blog/llm-model-routing)).
- **Local models for tools:** one May 2026 preprint found small open-weight models at parity with a frontier model on simple single-tool tasks, clearly behind on the hardest tier, with no open model reaching 80 percent on sequential two-tool chains; its authors say harder tiers need reduced reliability, a model-specific fix, or a frontier API ([AgentFloor](https://arxiv.org/pdf/2605.00334)). Blog comparisons of self-hosting servers report similar multi-turn tool scores but are not controlled studies, and note that serving defaults such as context size can change behaviour ([comparison](https://machinelearningmastery.com/?p=24950), [Red Hat on sovereign inference](https://www.redhat.com/en/blog/why-self-hosted-inference-essential-building-reliable-sovereign-inference-layer)). Nothing found tests customer-support agents specifically.
- **Implication:** route by rules the operator controls (data policy first), gate each local model by the agent's own scenarios, start local models on read-only single-step work, and treat learned routing as a later experiment. See `04-ai-architecture/NorthCX_Hybrid-Model-Selection.md`.

## 13. Personal intelligence in a consumer assistant (searched 2026-11-09)
Sources are mostly third-party write-ups from early 2026; coverage of custom assistants and scheduled actions was thin. Reported: Gemini's Personal Intelligence is opt-in and off by default, the user picks which apps to connect (Gmail, Photos, Search, YouTube at launch) under Settings, Personal Intelligence, Connected Apps, and it was a beta for paid subscribers in the US; it is not used for every reply, only when judged helpful, and tries to cite or explain what it used; saved info is a list of facts the user can add, edit or delete; passive context pulls from connected apps without the user stating it; activity controls include seeing what was used, temporary chats that are not saved, and deleting history; custom assistants ("Gems") let a person make an expert on a topic with instructions and uploaded files ([DataCamp](https://www.datacamp.com/blog/gemini-personal-intelligence), [Gend](https://www.gend.co/blog/google-personal-intelligence-expands-empowering-more-users), [Fortune](https://www.fortune.com/2026/01/14/google-gemini-ai-personal-assistant-gmail-photos-youtube-history-personal-intelligence), [Google's overview](https://gemini.google/overview/personal-intelligence)). I found nothing confirming how custom assistants use personal context or how scheduled actions work. What carries over to NorthCX: opt-in, per-source consent, "say what you used", temporary chats, a visible activity log, and person-built assistants; what must differ: a work setting with customer data, so personal context never stores it and administrators can lock it off.

## 14. Personalization layers in Claude and Codex (searched 2026-11-09)
Mostly third-party write-ups, some low quality; check the vendors' own help pages before relying on specifics.
- **Claude:** account-wide instructions applied to every new chat; styles (tone, voice and detail presets, with uploaded writing samples), reportedly moving toward skills although both surfaces work; projects as isolated workspaces with their own history, knowledge, instructions and memory; skills as reusable behaviours that load only when relevant; and an automatic memory layer (reported rollout March 2026) that can also be told to remember something, found under Settings, Capabilities ([CO/AI](https://getcoai.com/news/claude-gets-4-new-personalization-features-to-remember-your-work-style/), [Tom's Guide](https://www.tomsguide.com/ai/claude-just-got-a-major-personalization-upgrade-heres-whats-new), [how Claude's memory works](https://www.graduateschool.edu/learn/ai/claude-memory), [AI UX teardown](https://aiuxplayground.com/teardowns/claude/personalization)).
- **Codex:** three separate layers described by OpenAI: layered instruction files (a global one, then files from the project root down, merged with the closer file winning, with a size limit) that shape behaviour; memories that carry local context forward, off by default, enabled under Settings, Personalization; and skills and MCP for repeatable work and outside systems. Its memory is a separate store from the chat product's, it does not read other products' instruction files, and an explicit instruction file overrides a fuzzy remembered preference. One third-party piece warns of over-personalisation, where memory makes the agent agree with the user instead of the codebase ([Codex customization](https://developers.openai.com/codex/concepts/customization), [Codex memories](https://developers.openai.com/codex/memories.md), [over-personalisation](https://codex.danielvaughan.com/2026/06/12/codex-cli-memory-over-personalisation-sycophancy-risk-configuration-defence/), [memory pipeline](https://codex.danielvaughan.com/2026/04/18/codex-built-in-memory-system-deep-dive/)). I found no authoritative description of the chat product's own personality setting.
- **What carries over:** separate layers (instructions, style, memory, skills, project scope) rather than one blob; explicit instructions beat memory; closer scope wins; memory off or opt-in with an easy "without memory" option; project-scoped memory that does not leak; skills that load on demand; and guarding against memory that flatters.

## 15. Chat-window features in two agent platforms (searched 2026-11-09)
Third-party guides plus some product pages; feature names and limits vary between sources, so treat details as provisional. **Manus:** the input acts as a task bar (with scheduling, wide research and playbook options) rather than a plain chat box; a "Computer" side panel shows the agent's live activity (pages opened, files written) and lets the user pause, redirect and replay; projects keep shared instructions and files so new tasks start with context; a knowledge feature recalls saved preferences and practices (one guide reports a cap of 20 entries); scheduled recurring tasks; connectors to email, calendars, documents and CRMs ([Manus docs](https://manus.im/docs/features/overview), [composer teardown](https://aiuxplayground.com/teardowns/manus/composer), [feature guide](https://www.gadgetreview.com/manus-ai-features-that-actually-do-your-work-for-you)). **Kimi:** deep research asks clarifying questions and shows a research plan before searching, can keep running in the background and takes follow-ups in the same session; response modes (Instant, Thinking, Agent, and per one review Agent Swarm); a sidebar of outputs such as slides, docs and websites; files can be uploaded in chat and a whole session deleted; I could not confirm current upload limits ([Kimi deep research](https://www.kimi.com/en/features/deep-research), [help center](https://www.kimi.com/help/getting-started/overview)). **Shared pattern:** conversation in the middle, a live activity panel at the side, background work, projects with their own files and instructions, and steering or stopping a run. See `07-design/NorthCX_Admin-Platform-Design.md` section 0g.
