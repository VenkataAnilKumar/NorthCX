# Guided Studio: Phase 4 design

Status: stages 1 to 4 written 2026-11-22. **WP 4.2 is built** (R3, R4); the rest is not. Plan: `../12-project/NorthCX_Agent-Platform-Plan.md`, Phase 4. Design source: `../00-platform/NorthCX_Agent-Platform-Design.md`, section 7.

**Who it is for.** A CX lead or operations person who has never written YAML. They should be able to go from "I want an order-status agent" to a live, tested agent, and always see in plain words what the agent can do and what needs a person.

## The journey, in six steps
1. **Start**: a template from the Hub, or from the author's own procedures (Build).
2. **Connect**: tools chosen from the catalogue by plain name, each marked "reads" or "changes things".
3. **Procedures**: the instructions and the journey steps, written in plain words.
4. **What this agent will do**: a plain summary generated from the definition, with what needs a person's OK.
5. **Try it**: type a customer message, see the answer and the steps in words, make a good or bad conversation a test.
6. **Release**: a checklist in plain words; the release path itself does not change.

## Design
- **One definition.** The agent spec stays the source of truth; every screen edits it through the existing routes. The guided page keeps no state of its own beyond "which step is open".
- **Summary and checks are backend functions** (`northcx/plain.py`), tested in Python and returned by the existing preview route as additive fields (`summary`, and `problems` as objects with `message` and `fix`), so every client gets the same words.
- **`approvals.always`** is a new optional spec field: a list of tool names. The runtime holds a call to a listed tool through the approval path, with the reason "Your team set this action to always need a person's approval", unless the tool already has its own reason. It is validated (names must be tools the agent has) and left out of the digest when empty.
- **Try a draft** is `POST /v1/agents/{id}/try` with a spec and a message: the spec is built, the message runs in a sandbox like the rerun (own stores, simulated writes, the real model, counted against the budget) and the answer and trace return. Nothing is saved.
- **Guided page** is a Studio page of steps over the existing screens' components and routes; it links out to the full editor ("Advanced") and shows YAML only there.

## Decision 208
The guided path is a screen over the existing engines, with two additions the author cannot do today: a spec-level way to require approval, and plain-language checks. It does not add a second definition format, a workflow engine or a store. Order status and refunds already ship as templates, so WP 4.4 is a test, not a build.

## Limits and what is unverified
- Nothing here has been used by a CX lead. The time a first agent takes is unknown until WP 4.8; no figure is claimed.
- "Qualified model" results do not exist (no real-model pass has run); R9 and the second half of R7 cannot be completed honestly until one does.
